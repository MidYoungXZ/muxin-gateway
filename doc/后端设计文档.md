# Muxin Gateway 网关系统后端设计文档

## 1. 项目概述

### 1.1 项目背景
Muxin Gateway 是一个基于 Netty 的高性能 API 网关系统，采用模块化设计，支持独立运行和 Spring 生态集成。

### 1.2 设计目标
- **高性能**: 支持高并发的管理操作，不影响网关核心性能
- **安全性**: 完善的认证授权机制，保护系统安全
- **实时性**: 提供实时的监控数据和配置更新
- **可扩展**: 模块化设计，便于功能扩展
- **易维护**: 清晰的代码结构和完善的日志系统

### 1.3 技术选型

| 技术组件 | 选型 | 说明 |
|---------|------|------|
| 框架 | Spring Boot 3.3.5 | 简化开发，易于集成 |
| 数据库 | MySQL 8.0 | 关系型数据库 |
| ORM | MyBatis-Flex 3.9.8 | 灵活的数据访问框架 |
| 认证 | Sa-Token 1.37.0 | 替代 Spring Security，更轻量 |
| 注册中心 | Nacos 2.0+ | 服务注册与发现 |
| API文档 | SpringDoc OpenAPI 3.0 | 自动生成API文档 |
| 日志 | Log4j2 | 异步日志框架 |
| 网关核心 | Netty 4.1.115.Final | 高性能网络框架 |

> **实现状态说明**：
> - ✅ 表示已实现
> - 🚧 表示部分实现
> - ❌ 表示未实现

## 2. 系统架构设计

### 2.1 整体架构

### 2.2 核心模块说明

#### 2.2.1 gateway-core-plus（网关核心）

**设计目标**：
- 轻量级独立运行，不依赖 Spring Boot
- 协议无关设计，支持 HTTP、gRPC、WebSocket、TCP 等
- 高性能架构，基于 Netty 异步非阻塞 I/O
- 简化的架构，移除冗余的 Manager 层

**核心组件**：
```java
// 完整的生命周期管理
GatewayBootstrap ✅
├── GatewayProcessor ✅           # 核心请求处理器
├── RouteManager ✅               # 路由管理器
├── InstanceManager ✅            # 服务实例管理器
├── ConnectionPoolManager ✅      # 连接池管理器
└── NettyHttpServer ✅            # HTTP 服务器
```

**架构简化成果**：
- ✅ 移除了独立的 FilterManager、LoadBalanceManager、PredicateManager
- ✅ 功能集成到 RouteConfigConverter，使用 Factory 模式
- ✅ 每个路由完全隔离，避免配置冲突
- ✅ 支持全局配置和路由级配置继承

#### 2.2.2 gateway-admin（管理后台）

**模块职责**：
- 提供 RESTful API 接口
- 网关配置管理（路由、过滤器、负载均衡）
- 用户认证授权（Sa-Token）
- 监控数据收集和展示
- 操作日志记录

**技术特点**：
- Spring Boot 3.3.5 框架
- MyBatis-Flex 数据访问
- Sa-Token 认证授权
- WebSocket 实时通信
- SpringDoc API 文档

#### 2.3.2 请求处理流程（优化线程模型）
```
客户端请求 → NettyHttpServer → GatewayProcessor → 请求处理流水线
                                      │
                    ┌─────────────────┼─────────────────┐
                    ▼                 ▼                 ▼
                 1. 请求验证        2. 协议转换      3. 路由匹配
                    │                 │                 │
                    ▼                 ▼                 ▼
                 4. 前置过滤        5. 负载均衡      6. 连接管理
                    │                 │                 │
                    ▼                 ▼                 ▼
                 7. 后端调用        8. 后置过滤      9. 协议转换
                    │                 │                 │
                    └─────────────────┴─────────────────┘
                                      │
                                      ▼
                                 响应返回客户端

**线程模型优势**：
- 同步执行阶段（CPU密集型）：步骤1-6，当前线程连续执行
- 异步执行阶段（I/O密集型）：步骤7-10，业务线程池执行
- 单次线程切换：从10次优化到1次，减少90%线程切换开销
```

#### 2.3.3 协议系统

```java
public interface Protocol {
    String type();                    // 协议类型 (HTTP, TCP, UDP等)
    String getVersion();              // 协议版本

    boolean isRequestResponseBased(); // 是否请求-响应模式
```

```java
public interface Message {

    MessageMetadata getMetadata(); // 元数据

```

#### 2.3.4 路由系统

**Route 接口**：
```java
public interface Route {
    String getId();
    Protocol getSupportedProtocol();          // 支持的协议
    List<Predicate> getPredicates();          // 断言列表
    List<Filter> getFilters();                // 过滤器列表
    RouteTarget getTarget();                  // 目标服务配置
    boolean matches(RequestContext context);  // 匹配请求
}
```

**路由配置示例**：
```yaml
routes:
  - id: user-service
    name: 用户服务路由
    order: 1
    enabled: true
    supportProtocol:
      type: HTTP
      version: "1.1"
    predicates:
      - type: PATH
        patterns: ["/api/users/**"]
      - type: METHOD
        methods: [GET, POST]
    filters:
      - type: AUTH
        order: 1
        config:
          authType: JWT
          secretKey: "your-secret-key"
      - type: REQUEST_LOG
        order: 2
        config:
          includeHeaders: true
    target:
      type: SERVICE_DISCOVERY
      serviceName: user-service
      loadBalance:
        strategy: ROUND_ROBIN
    timeouts:
      connect: 5s
      request: 30s
```

## 6. 性能优化

### 6.1 gateway-core-plus 性能优化

#### 6.1.1 线程模型优化
- **单次线程切换**：从10次优化到1次，减少90%线程切换开销
- **CPU 亲和性**：同步操作连续执行，提高 CPU 缓存命中率
- **异步 I/O**：I/O 密集型操作异步执行，不阻塞主线程

#### 6.1.2 内存优化
- **对象池化**：复用频繁创建的对象
- **零拷贝**：使用 Netty 的零拷贝特性
- **缓存优化**：使用 Caffeine 高性能缓存

#### 6.1.3 网络优化
- **连接池**：复用后端连接，减少连接开销
- **TCP 优化**：调整 TCP 参数，提高传输效率
- **背压控制**：防止内存溢出
