## Context

当前路由详情对话框使用 el-descriptions 和简单的 el-table 组合展示数据，存在以下问题：

1. **数据显示错误**：断言配置表格使用 `row.config` 显示配置，但后端返回的实际字段是 `row.args`
2. **布局简陋**：使用单一表格展示，缺乏视觉层次
3. **配色单调**：未充分利用 Element Plus 的主题色和标签系统
4. **JSON 展示不友好**：使用简单的 `<pre>` 标签，无语法高亮和折叠功能

## Goals / Non-Goals

**Goals:**

- 修复配置列数据显示错误
- 使用卡片式布局分组展示不同类型的信息
- 优化配色方案，提升视觉层次感和美观度
- 改善 JSON 配置的可读性
- 添加状态标签和图标增强信息表达

**Non-Goals:**

- 不修改后端 API 或数据结构
- 不添加新的功能或字段
- 不修改路由表单或创建/编辑流程
- 不引入新的第三方库（如 JSON 编辑器）

## Decisions

### 决策 1：使用卡片式布局分组展示信息

**选择：** 将路由详情分为三个卡片区域：
1. 基本信息（路由ID、名称、URI、状态等）
2. 断言配置列表
3. 插件配置列表

**理由：**
- 提升信息层次感，便于用户快速定位
- 符合现代 UI 设计趋势
- Element Plus 的 el-card 组件支持良好的样式定制

**替代方案：** 继续使用 el-descriptions 和单一表格 - 拒绝，因为缺乏层次感

### 决策 2：优化 JSON 配置展示格式

**选择：** 使用 `<pre>` 标签配合自定义 CSS 样式，添加背景色、边框、圆角和合适的字体大小。

**理由：**
- 保持轻量级，无需引入额外库
- 通过 CSS 即可实现良好的视觉效果
- 支持滚动查看长 JSON

**替代方案：** 引入 Monaco Editor 或 CodeMirror - 拒绝，因为过于重量级且增加复杂度

### 决策 3：使用状态标签和图标增强可读性

**选择：** 为关键字段添加 el-tag 标签和图标：
- 状态（启用/禁用）：使用 success/danger 类型的 tag
- 负载均衡策略：使用 info 类型的 tag
- 断言/插件类型：使用不同颜色的 tag 区分
- 优先级：使用徽章或标签显示

**理由：**
- 增强视觉识别度
- 符合 Element Plus 设计规范
- 提升用户体验

### 决策 4：修复数据绑定错误

**选择：** 将断言配置表格中的 `row.config` 改为 `row.args`。

**理由：**
- 后端返回的断言数据结构使用 `args` 字段存储配置
- TypeScript 接口定义中已包含 `args` 字段
- 这是数据绑定的错误修复，不是 API 变更

## Risks / Trade-offs

### 风险 1：样式变更可能影响暗黑模式

**风险描述：** 自定义样式可能未充分考虑暗黑模式的适配。

**缓解措施：**
- 使用 Element Plus 的 CSS 变量（如 `var(--el-bg-color)`）
- 测试亮色和暗色主题下的显示效果
- 避免硬编码颜色值

### 权衡 1：展示美观度 vs 代码复杂度

**权衡描述：** 更美观的展示需要更多的自定义样式代码。

**决策：** 优先保证可读性和美观度，适度增加样式代码。使用 scoped CSS 避免全局污染。
